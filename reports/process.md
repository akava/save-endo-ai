# Как шла работа

Журнал процесса: что делал, в каком порядке, какие решения и почему.

## 0. Исходные данные

- `doc/Endo.pdf` — спецификация ICFP Contest 2007 «Morph Endo!» (22 стр.). Текст извлечён через `pypdf` во временной venv.
- `doc/endo.zip` → `endo.dna` (7 523 060 оснований).
- `doc/Source-image.png`, `doc/Target-image.png` — **300×300 RGBA**, то есть уменьшенные копии оригиналов 600×600. Сначала пользователь дал 150×150, потом заменил на 300×300.
- Условия пользователя: решаем честно, **без интернета и без опоры на опубликованные решения**. Цель — дойти так далеко, как получится. Коммитить по мере прохождения этапов в ветку `main`.

## 1. Выбор стека

- Ядро на **C++17 (clang)**, потому что нужна скорость: эталонный прогон делает 1,9 млн итераций по строке длиной до 17 млн.
- Обвязка на **Python** (`.venv`: pillow, numpy): генерация префиксов, рендер, оценка, монтажи картинок.
- PNG пишется своим кодом через zlib, без внешних библиотек.

## 2. Исполнитель DNA→RNA (`src/dna.cpp`)

- **Версия 1:** неявный treap, где каждый узел — кусок (offset, len) в append-only арене. Шаг выполнения: читаем pattern и template курсором с начала, без изменения дерева; матчим; делаем один `split` в позиции `p0+i`; строим замену и выполняем `merge`.
  - Сразу совпали все эталоны из спецификации: **1 891 886 итераций, 302 450 RNA, cost 192 646 205**, а также 3 примера из Figure 16.
  - Время работы 27 с.
- **Версия 2:** **персистентный treap**. Узлы неизменяемы, `merge` рандомизирован по размерам поддеревьев, потому что одни и те же поддеревья могут встречаться несколько раз. Ссылка `\n` без квотирования копирует поддерево за O(log n), а не кусок за куском. Есть GC: дерево перестраивается в сбалансированное, когда пул превышает 6 млн узлов.
  - Время сократилось **до 2 с**, RNA побайтно совпадает с версией 1.
- Вопрос со стоимостью `protect` (считать ли каждый уровень рекурсии) решился сам: при подсчёте только финальной длины эталонный cost совпал точно.

## 3. Builder RNA→PNG (`src/build.cpp`)

- Ведро цветов хранится как суммы и счётчики. Flood fill сделан итеративным, на стеке. Линия, compose и clip реализованы строго по спецификации.
- Флаги: `--layers` выгружает все слои, `--stop N` останавливает после N команд.
- Проверка: исходная картинка рендерится правильно. Префикс-подсказка из спецификации показывает экран SELFCHECK, где **все 25 тестов OK**.

## 4. Оценка близости к target

- Target известен только в 300×300 и с искажениями: даже наш рендер source после усреднения 2×2 расходится с `Source-image.png` в среднем на 1–6 единиц. Точного попиксельного совпадения нет ни при одном методе уменьшения (nearest, box, bilinear и т. д.).
- Метрика (`tools/endo.py: score`): рендер усредняется 2×2 и сравнивается с target. Пиксель считается неверным, если отклонение больше 24 по любому каналу; результат умножается на 4. Это **приблизительная** оценка числа неверных пикселей 600×600. Наш рендер source против Source-image даёт 7,7% «ошибок», в основном на границах из-за сглаживания.

## 5. Инструменты исследования

- `-t FROM TO`: трасса итераций (pattern, template, успех матча, длины окружения).
- `-L file`: **журнал происхождения**. Для каждого сравнения с константой и для каждого копирования фрагмента пишется, какому месту **исходной** DNA он соответствует (по offset в арене). Так флаги и гены видны в координатах исходного файла, хотя DNA постоянно сдвигается.
- `tools/endo.py`: кодировщики (`nat`, литералы, конструкторы pattern и template), `set_base(pos, base)` для переключения одного основания, `run()`, `score()`.

## 6. Техники исследования

- **Дифференциальный анализ одного основания.** Меняем одно основание исходной DNA префиксом `set_base(pos, b)`. Pattern `(!pos)!1`, template `\0 b`. Затем сравниваем картинку, число итераций и RNA с эталоном.
- **Поиск флагов по журналу происхождения.** Отбираем записи `B`, где код сравнивает основание исходной DNA с константой и не совпадает (ожидает `P`, видит `F`). Это кандидаты в выключенные условия.
- **Поиск генов по журналу происхождения.** По записям `R` (какие диапазоны исходной DNA копируются шаблонами) видно, какие куски вызываются и сколько раз.
- **Монтаж картинок.** Несколько рендеров склеиваются в одну сетку, чтобы сравнить их одним просмотром.

- **Карта генов.** Сырой эпилог гена встречается в DNA 250 раз. Начало гена находится по шаблону «24-слово + `III` + ID». Результат лежит в `out/genes.json` и `out/gene_ids.json`.
- **Восстановление вызовов из трассы.** Pattern вида `(!A(!L))` с template `\0\1` — это вызов. Группировка по A+L даёт границы функций.
- **Дизассемблер** (`tools/disasm.py`): линейно декодирует pattern/template с любого адреса и показывает skip-адреса, ссылки и литералы.
- **Дерево вызовов из RNA** (`tools/rnatree.py`): ID-маркеры на входе и `CFPICFP` на выходе дают вложенность, для каждого узла считаются рисующие команды.
- **Абляция на уровне RNA.** Из потока вырезаются рисующие команды поддерева, команды слоёв (`addBitmap`, `compose`, `clip`) остаются. Картинка перерисовывается, всё складывается в монтаж с подписями. Так быстро видно, какой ген какой объект рисует. Ограничение: если вырезать линии, ломаются последующие заливки.
- **Дешёвые патчи через ссылки.** Вместо литералов template копирует уже существующие куски DNA (`\1 \1`). Префикс выходит короче.
- **Заглушка гена** (`stub_gene`): в начало тела пишется `!N` прямо на эпилог. Работает только для генов, которые не трогают стек.

- **Вызов произвольного гена** (`call_from_exit`). `main` заканчивается вызовом exit (G+2248207), который обрывает DNA и не возвращается. Его 394 основания переписываются на `call X` с возвратом в эпилог другого гена, и X выполняется поверх готовой сцены. Ранние неудачи: (1) добавлять кадры в загрузчик бесполезно, потому что `main` не возвращается; (2) в префиксе из нескольких инструкций skip-адреса отсчитываются от остатка префикса. Отсюда `combine(...)`: каждый патч получает `off` = длину хвоста префикса.
- **Изоляция** (`tools/ablate.py ... iso`): в RNA оставляется только поддерево одного гена плюс операции со слоями. Даёт чистое изображение объекта.
- **Массовый перебор генов** (`tools/try_genes.py`): 12 потоков, таймаут; затем отбор рендеров, отличающихся от базового, и рендер только RNA после ID вызванного гена.

## 8. Облачная сессия (Linux, 4 ядра)

- Сборка `make CXX=g++`; `endo.zip` распакован через python `zipfile`. Эталонный прогон совпал, около 6 с.
- Повторный прогон 21 гена, упавшего по таймауту, с лимитом 400 с. Почти все зацикливаются без аргументов. G+2211015 считал 83 млн итераций без рисования, G+2483201 нарисовал 27 млн RNA случайных линий. Вывод: перебор таймаутами бесполезен, нужен разбор вызовов.
- **Уточнение семантики:** окружение pattern пополняется на *закрывающей* скобке. Поэтому в вызове `!rest(!A(!L)!B)` → `\0 \1 word word` ссылка `\0` указывает на вызываемый ген, а `\1` — на весь геном. Новая DNA: `[ген][геном][кадр][память]`.
- **Статический граф вызовов** (`tools/callgraph.py` → `analysis/callgraph.json`): дизассемблируются все гены и ищутся инструкции вызова. Гены группируются по набору вызываемых, так нашлись серии страниц.
- `tools/render_genes.py OUT W gene…`: вызвать набор генов-корней и собрать подписанный монтаж.
- **Таблица генов.** Строковые литералы расшифрованы (EBCDIC−64, `tools/strings.py`), в `printGeneTable` найдена таблица из 400 имён с адресами и размерами (`tools/genetable.py`). Дальше всё ищется по именам.
- **Карта проверок** (`tools/flagrefs.py`): для каждой условной инструкции `!k(!N lit)` вычисляется проверяемый адрес генома и сопоставляется с именем глобальной переменной. **Поток управления гена** (`tools/flow.py`): вызовы с именами, условия, переходы, RNA.
- **Field Repair Manual:** страницы перебираются через `helpScreen` (номера взяты из сравнений в `main`). Самое полезное: Adapter (85), зоны (1729), безопасность (4405829, ROT13).
- **Adapter:** `push_arg`, `adapter_call`, `crypt_call` в `tools/endo.py`; аргументы кладутся в порядке сигнатуры.
- **Криптоанализ:** дамп DNA (`--dump -n N`) до и после `crypt` → поток ключа → совпадение с RC4. Свой переборщик `tools/c/rc4crack.c` подбирает ключ из 3 символов за доли секунды (внутри DNA на это уходили десятки минут).
- **Ремонт мутаций** тремя способами: (1) по гену-«близнецу» с той же структурой (`sun` ↔ `lightningBolt`); (2) по зеркальной резервной копии (`cloud` ↔ `duolc` задом наперёд); (3) через ECC-данные и ген `correctErrors` (`cow-spot-middle`).
- **Патчи без изменения длины:** пустая инструкция `noop(n)` (`!0` с нулями в nat), перекодирование чисел с дополнением нулями до прежней длины, правка литералов сравнений (`weather == 2` → `== 0`), правка таблицы распаковщика RNA.
- **Минимизация префикса:** группы исправлений по одной выкидываются, и проверяется, что md5 RNA не изменился (`out/min_cloud.py`, 6 из 47 оказались лишними).
- Ошибки по ходу: (а) `pkill -f` с шаблоном, который совпадает с собственной командой, убивает свою же оболочку, так что PID надо искать через `ps | grep [x]`; (б) патчи с абсолютными смещениями должны знать длину хвоста префикса, поэтому всегда `combine(...)`, а вызовы через Adapter идут *перед* патчами; (в) `write_at` сам кодирует литерал, повторно кодировать нельзя.
